# 账本设置与供应商配置

## 设置入口

当前 DSH 使用插件 Config 作为配置契约，不再支持旧版 `settings.register()` / `settings.get()`。本分支已迁移到 Config，非敏感的 `relays`、`rates`、`endpoints` 为 volatile 字段，保存通过宿主 Settings 服务进行字段级变更，附带读取时的 revision；其他窗口修改配置后，旧窗口保存会被拒绝，须重新加载后再编辑。

设置首项为“默认显示账户”，选项来自当前发现的账户。选择后点击“保存设置”，新打开的账本会优先查询并显示该账户；在账本中临时切换账户不会修改默认值。保存设置后当前账本也会重新应用默认选择。选“自动选择”时使用首个可用账户，已删除或不可用的默认账户也会自动回退，不影响其他统计。

设置界面还提供路由覆盖、模型费率、自定义余额端点三项 JSON 编辑。路由与供应商地址通常自动从 DSH 的 provider 配置发现；只有需要覆盖或补充时才填写。不要在这三个字段里填写 API Key 或用户中心令牌。

- `relays`：以实际 provider 路由名为键，填写站点地址或覆盖对象。
- `rates`：填写费率数组；`null` 表示恢复默认费率行为，未定价模型不显示虚构的零费用。
- `endpoints`：填写自定义余额端点数组；只允许现有 provider 同源地址，不能用该设置指定任意凭据或跨源请求。

数据库路径、命令名称和定时扫描间隔属于启动配置，本设置页不修改这些字段，避免在保存过程中更换运行实例或索引文件。

## 供应商与历史归属

当前目录从 `llm.listConfigurableProviders()` 找到准确的 settings namespace 与路径，再从 ConfigEditor 所有的 `entry.fiber.effectiveConfig` 读取对应 provider 字段。嵌套 volatile 配置只沿所需路径解引用，不将原始 API Key、headers 或其他配置复制到页面。Settings.describe 的表单只含 volatile 字段，因此不能用它的字段缺失推断普通 provider 配置也不存在。

余额读取保存同一次操作的 origin 与 API Key 引用，读取时才通过凭据服务解析。目录不可读、配置缺失或路由已删除时不把它猜成 DeepSeek 官方。目录恢复后，现有归属检查会重建派生索引，让历史请求重新归位。已删除或改名且无法恢复的路由继续显示“未知路由”。

## 钱包查询凭据

识别为 New API 的余额卡片提供“设置查询API”。新保存的用户 ID 与系统访问令牌存放在宿主 credentials record 中，不写入普通插件配置；页面读取仅得到用户 ID 和令牌是否已设置。

保存目标必须是当前发现的账户 origin；修改只作用于该站点。已存在令牌时可只更新用户 ID，留空令牌表示保留原值。删除只删除本插件的对应记录。

旧版 `userAuth` 配置作为只读兼容来源。若原配置仍有有效旧令牌，删除新记录会被拒绝，避免旧令牌自动回退复活；需先在原配置中移除旧来源。本轮没有自动迁移或删除用户原有凭据。

## 验证边界

迁移使用当前 DSH 0.2.2-rc.3 的安装源码、实时 Config Inspect 及合成测试验证。真实 SettingsForms 的隔离检查覆盖 Config 投影、volatile 更新和过期 revision 拒绝。配置 UI 和供应商余额仍应在实际 Desktop 页面检查；不能把单元测试或 Config schema 可见视为全部真实交互通过。
